# The Music Constellation — agent context

One web app, four genre constellations (jazz, hip hop, reggae, classical). No build step, no dependencies: plain HTML/CSS/JS served by GitHub Pages from this repo's root. Live at https://hueyb-art.github.io/the-music-constellation/.

## Architecture in one paragraph

`index.html` is the only page; genre data is **lazy-loaded** (see below); `js/engine.js` is the shared engine (canvas 3D force graph, search, panels, audio previews, live MusicBrainz/Wikipedia data); `js/data/<genre>.js` files register curated datasets on `window.GENRE_DATA`; the engine's `loadGenre()` swaps dataset + theme in place, `switchGenre()` animates the swap, and `#/jazz`-style hash routes select the genre. Genre themes are CSS custom properties registered with `@property` so they cross-fade.

## The workflow (non-negotiable)

1. Make changes (data lives in `js/data/`, never in the engine).
2. `node scripts/validate.mjs` — must pass before any commit. It catches duplicate ids, dangling edges, missing fields, bad regexes, syntax errors.
3. Bump the date in `js/version.js` for user-visible changes.
4. Commit with a real message (not "Add files via upload") and push. CI re-runs validation; Pages republishes in ~1 minute.

Huey's standing rule: always commit AND push when validation passes — but ask questions first if you're about to change something structural.

## Views

Four view modes in engine.js, all genre-themed and routed via the hash:
- **globe** (`#/<genre>`, default) — the 3D force-directed constellation.
- **holo** (`#/<genre>/holo`) — a real **WebGL** rendering of the globe, in `js/holo.js`, lazy-loading three.js (via the index.html import map) only when entered, so the 2D site stays dependency-free. It reads the live data + positions the engine already simulates (`window.MCH`, set each `loadGenre`) and on tap calls `MCH.select(node)` — so it **inherits the genre switcher, artist card, audio playback and Rooms for free**; clicking a star opens the same panel. Always-on collision-avoided name labels (HTML projected each frame), hover/tap lights a star's gold ties + neighbour names, OrbitControls (drag/zoom, `zoomToCursor`, slow `autoRotate`). `setView("holo")` hides `#stage`/spread and calls `HOLO.enter()`; the loop's holo branch runs `step()` (live drift) + `HOLO.frame()`; a genre swap calls `HOLO.rebuild()`. `js/holo.js` must load **before** `js/engine.js` so `window.HOLO` exists when a `/holo` route is honoured at startup. (`lab/holo.html` is the original standalone prototype, now superseded by this in-app view.)
- **chord** (`#/<genre>/chord`) — everyone on a ring by era, ties arcing to a living sun, ambient slow spin, deep-space backdrop. **Two-step, silent interaction (NOT the globe's `select()`):** clicking goes through `chordPick()` — 1st click anchors a star (sets `chordAnchor`/`selNode`, lights ties via `computeFocus`) with no card and no audio; 2nd click on one of that star's ties calls `renderChordCollab()`, which opens the side panel as a breakout card (the pair, the relationship chip, and the shared records via the shared `loadCollabInto()` loader) **and plays a preview of one of those shared records** (`playCollabClip()` — Deezer search verified to a collaborator/band, cached per pair under `cclip_<a>_<b>`; the anchor/re-anchor/clear/close paths pause it so audio only sounds while a collab card is open). Clicking a non-tie star re-anchors; empty space clears; the panel close button keeps the anchor (drops back to anchored-and-silent) in chord. `dblclick`→full-page is disabled in chord. Self-contained `drawChordView()` + `drawChordSpace`/`drawSunCorona`/`drawRingFire`; node ring angle is `nd._cang` (set in loadGenre, ordered by era to match the era arcs). `nodeAt()` in chord is **angle-based**: the stars are tiny dots on a thin ring, so instead of hit-testing each dot (you'd have to land exactly on one — "no names when scrolling around" was this), it returns the star whose ring angle (`_cea`) is nearest the cursor's, for any cursor in the ring band (`R*0.6`–`R*1.25`). Hover and click are both forgiving as a result. The highlight is `active=selNode||hoverNode` — the **anchor sticks** (once you click a star its web stays put so you can follow the lines and click its collaborators); hover only previews names *before* anything is anchored. (We briefly tried `hoverNode||selNode` so hover would follow the cursor even while anchored — it broke "click a star then click its collaborator", because the web jumped to whatever you moved over. Don't reintroduce it.) On **touch** there's no hover, so a tap is the only aim — to make selecting a connection reliable, the connection **names** are registered as tappable hitboxes (`chordLabelBoxes`, rebuilt each frame in `drawChordView`; `nodeAt` checks `chordLabelAt` *before* the angular ring test). Tapping a de-collided name selects exactly that artist rather than an angular neighbour. Names/spacing are larger on mobile, and the touch-move handler has a ~10px tap-slop so a wobbly tap isn't misread as a pan. `setView()` switches modes and writes the hash; `parseHash()`/`updateHashView()` keep URL ↔ view in sync; `switchGenre()` preserves the current view in the hash. (`parseHash()` recognises `chord` and `holo`; anything else — including stale `#/<genre>/timeline` links from the removed Timeline view — maps to globe.)

**Selection follows you across views.** `selNode` is the unified "who's selected" in all three modes (globe `select()`, chord `chordPick()`, and a 3D tap's `MCH.select()` all set it). `setView()` captures it into a local `carry` *before* the per-mode `deselect()` runs, then re-applies it on entry — **silently** (no clip replay): globe & holo re-open the card (`select(carry,true)` — the `quiet` arg skips `playClip`), holo also re-lights the 3D ties via `HOLO.enter(carry)`, and chord re-anchors via `chordPick(carry)` (its native card-less state, so you can click a tie to dig into the collab). No new persistent state and no `loadGenre` change is needed — a genre swap doesn't go through `setView` and already nulls `selNode`, so a selection never leaks across genres.

## White-label & poster export

`window.MC_CONFIG` (index.html; defaults reproduce the public site) makes the engine rebrandable — `brand`, `tagline`, `genres`, `showTabs`, `accent`, `attribution`, `kiosk` — and every key is overridable from the URL query string (e.g. `?brand=Blue+Note&genres=jazz&tabs=0&accent=%231e63b0`). `CFG`/`BRAND`/`TAGLINE`/`SINGLE` are computed near the top of engine.js; brand text is set via `textContent` (URL-param-safe). The **Poster** button (`exportPoster()`, desktop only) renders the current view to a 4000px PNG by temporarily resizing the main canvas with a scaled transform (so label fonts scale up), drawing once, exporting, and restoring in a `finally` — synchronous, no flash. Full docs: docs/WHITE-LABEL.md.

## The Rooms

The **Rooms** button (`rrBtn`, was "Reading room") opens `openRooms()` — one full-screen page (reusing `pageInner`/`pageEl`) with three tabs held in `roomTab`: **Reading**, **Films & docs** (`films`), **Deep cuts** (`deepcuts`). The **Reading** tab is a **lit bookshelf**: `roomReadingHTML()` lays out the shell (gilded back panel + two overhead picture lights `.rlamp` that rake warm light down) and `buildReadingShelf()` (called from `openRooms`) flattens `critics[].books` into clickable spines — the title (before any colon) + author gold-stamped on each — sized to the container into wood shelves (`layoutReadingShelf`, re-runs on resize). `loadReadCovers()` fetches each book's **real cover** (Open Library → Google Books, preloaded, cached under `tmc_olcov_*`; `rsToken` cancels stale loads on genre/tab change) and uses it as the spine art behind the title via `applyReadCover()`; books with no cover keep the gilded fallback (`RS_PAL`). Clicking a spine opens a detail card (`openReadBook` → `.bookcard-bg`, appended to `<body>`, closed on backdrop/✕/Esc and by `closePage`) showing the full cover, author, year, and the critic's note. Archives / Periodicals / Radio sit on a lower shelf (`.readmore`). The styling lives in css/style.css under "READING ROOM: the lit bookshelf". The **Films & docs** tab is the *same* shelf, generalised: `buildShelf(caseId, items, coverFn, onClick)` is shared, and `buildFilmShelf()` feeds it `FILMS` with `coverFilm` (each poster pulled from Wikipedia's `pageimages` for the matched film article — `generator=search` + `pilicense=any`, since posters are non-free) and `openFilmCard` (year · director, note, and YouTube/JustWatch links). Both rooms share `applyCover`/`loadShelfCovers`/`rsPreload`, the `_shelf`/`rsToken` state, and the `.bookcard` overlay; a missing poster falls back to a film-reel case. **Image matches are validated** (`titleOk(want,got)` — accept only if the article/book title starts-with or shares ≥60% of significant words; the film query is `title+year` *without* the director, so it can't match the director's bio page) and a film may pin its exact article via a `wiki` field. Covers/posters **cache hits only** (keys `tmc_olcov_*` / `tmc_poster_*`); a miss is never cached, so a transient failure self-heals instead of leaving a permanent blank — same rule as audio. **Deep cuts** stays a text list. Each tab has its own `room*HTML()` builder. Deep-cut entries with an `id` matching a node render the artist as a link that calls `openPage(nd)`; listen links come from the shared `svc()`. Data shapes and how to add entries are in docs/DATA-FORMAT.md. `films`/`deepcuts` are optional per genre (engine reads `G.films||[]`).

## Instrument tag

Every node carries `nd.roleTag` (the primary segment of its curated `role`, e.g. "Trumpet", "Arranger", "Producer"), set in `loadGenre`. Both views draw it as a small gold line under the name **only while exploring** — the hovered/anchored musician and their lit connections (globe gates on `focusSet`; chord shows it for every label, which are always the focus set). It's free across all genres because it reads the existing `role`. Changing what shows: globe in the name loop in `draw()`, chord in the `if(active)` label block in `drawChordView()` (note the de-collision `gap` and tap-hitbox were widened for the second line).

## Conventions and gotchas

- **All MusicBrainz access goes through `js/collab.js`** (`window.MB.get`), a single rate-limited request queue shared by discographies and collaboration lookups so they never collide on MB's ~1 req/sec limit. `window.MB.collab(nameA, nameB, cacheKey)` returns deduped shared recordings; used by the app's connection cards (the ♪ expander in `toggleCollab`) and the prototype's Solar view. Loaded before engine.js in index.html.
- **`js/data/*.js` are the canonical source.** `scripts/extract-legacy.mjs` and `port-engine.mjs` were one-time migration tools from the three legacy repos (../jazz-constellation etc.) and are frozen — re-running extract-legacy would resurrect data bugs that were fixed here after extraction (see docs/LEARNINGS.md).
- A pair of artists may have multiple edges with *different* relationships ("produced" + "crew"); the same relationship twice is a validation error.
- **Curated shared records** (`G.collabs`, optional per genre): the connection card's "Records together" pulls *co-credited* releases from MusicBrainz, which misses sideman/family sessions (one played on the other's leader date). `G.collabs` supplies hand-picked shared records for a pair — keyed by the two node ids **sorted + joined with `_`** (e.g. `"branford_wynton"`), value `[[year,title,note],…]`. `loadCollabInto` uses it authoritatively (short-circuits the MB lookup) when present. See the Marsalis family in js/data/jazz.js.
- **An artist's `bio` (7th `n()` arg) is a full ~6–8 sentence CV** shown on the breakout page (the `blurb`, 6th arg, stays the one-line tagline for cards). Bios must use **single quotes only** — never `"` (this applies to the three HAND-AUTHORED genres; classical is generated and every field goes through `JSON.stringify`, so quotes are escaped safely there) — since each node field is one JS double-quoted string; an unescaped `"` breaks the line. The CVs were generated by a verified write→fact-check fan-out (see docs/LEARNINGS.md, 2026-06-23); to re-expand a genre, extract nodes, run the pipeline, and apply with `/tmp/apply-bios.mjs` (replaces only the 7th arg, by id; handles escaped-quote names).
- Directional relationship words live in `REL_DIR` in engine.js (union across genres); symmetric words per genre in each data file's `sym`.
- localStorage keys are namespaced `tmc_<genre>_…` because this origin is shared with the legacy sites (which use `jc_…`). Don't change prefixes casually — it orphans users' caches.
- The iTunes relay (`https://jazz-itunes.hueyb.workers.dev`) is genre-agnostic despite the name; deployment guide in docs/itunes-relay-setup.md.
- **Audio previews prefer Apple, fall back to Deezer.** `playClip()` resolves iTunes first — Apple's preview audio is CORS-readable (so the now-playing waveform can decode the *real* signal) and its CDN is the robust one (not blocklisted, links don't expire) — then Deezer (JSONP search / pinned `did`), with a self-correcting play-error fallback between the two. Only *successful* URLs cache, under `clip2_<id>` (a miss never poisons; a cached URL that won't play is dropped and re-resolved). `ov.only` namesake artists stay Deezer-only. Collab clips (`playCollabClip`) still resolve via Deezer search. Why Apple matters historically: Deezer's signed/expiring/blocklisted previews caused the desktop "won't play" bug (see docs/LEARNINGS.md). **The track that plays is the artist's curated signature recording — `disco[0]`** (the title is the search seed). The resolver is title-aware: `itSearch`/`dzSearch` prefer the candidate whose title matches the seed (`trackTitleMatch`), else fall back to first-by-artist, so a non-song seed never drops coverage. `disco[0..2]` were curated by a verified fan-out (signature song first, original years) — see docs/LEARNINGS.md, 2026-06-23; re-curate with `/tmp/apply-tracks.mjs` (replaces only the disco array, by id).
- **Now-playing waveform** (`#clipnote` pill, `waveTick` in engine.js): a gold oscilloscope driven by the **decoded loudness envelope** at `clip.currentTime` for Apple clips (fetched + `decodeAudioData`, cached per URL), and a gentle *simulated* motion for Deezer-only clips (whose audio can't be fetched). It runs only while the `<audio>` element actually plays (driven by its `playing`/`pause`/`ended` events, so it covers main + collab clips). Not a live `AnalyserNode` — `createMediaElementSource` on the cross-origin element would output silence and break playback. The pill is positioned just under the topbar on each show (the topbar wraps taller as the window narrows). **Under the waveform a small box (`#cliptrack`) shows the playing sample's title and release year** — the resolver (`itSearch`) now returns `{url,title,year}` (Apple gives both; Deezer fallback usually title only), carried via `mainPlay`→`playPreview`→`setTrackInfo`; `clip2_<id>` caches `{url,title,year}` as JSON (old bare-URL caches still read). `clipNote()` clears the box on every call, so a successful play re-sets it. **The year is filtered through `trustYear(nd,apiYear,title)`** — iTunes returns *its catalogue item's* date, which for older recordings is usually a modern reissue/remaster (a 1939 Glenn Miller side as 1991), so we prefer the curated `disco` year when the playing track matches a curated record (`discoYear`), else accept the API year only if it's plausible for the artist's lifespan (`yearPlausible`, parsed from `nd.life`), else show the title with no year rather than a wrong one. In **chord/collab** the matched record's MusicBrainz year is appended inline in the pill (`♪ Record (1959)`), not the box.
- **3D node look** (js/holo.js): nodes are lit `MeshPhysicalMaterial` "velvet" spheres (a three-point light rig + ACES tone-mapping + a tiny `onBeforeCompile` fresnel emissive "wrap") — chosen over the old flat `MeshBasic` + sprite-halo look; focus pops a node via `scale` + `emissiveIntensity`. The look was picked from the comparison harnesses in `lab/` (`holo-nodes.html`, `holo-organic.html`; see docs/LEARNINGS.md, 2026-06-21).
- **Unified search** (`#q`): artist matches (name/role, typo-tolerant `searchScore`) **plus song matches** over `SONGS` — an index of every artist's curated `disco` titles, rebuilt per genre in `loadGenre` (~1,800 songs total). Song rows render `♪ Title — Artist · Year` under a "Songs" header; clicking one calls `pick(nd)` to jump to and select that artist. Scoped to the current genre (within-genre by design). Enabled by the signature-recordings pass (before it, `disco` was too sparse/album-heavy to search).
- Preview-test locally: `.claude/launch.json` serves the repo on :8741 (python http.server). The genre switch, search ("stephane" artist, "so what" song), node select, photo-zoom (`tzoom=1.8` after `centerOn`), and the Chord web toggle (ring stays grouped by era; globe re-inflates on return) are the key manual checks.
- **Timeline** (`#/<genre>/timeline`) — schools/movements as dated clusters on a year axis, ported from the art constellation on 2026-08-17 at Huey's explicit ask. This is NOT the old depth-voyage view (removed 2026-06-14 because he wanted globe + chord only); it is the dated-clusters design he liked in the art project. Offered only where a genre supplies dated groups (`G.schools` or `G.movements`) — so classical has it and the other three don't until their eras gain `s`/`e` years; `tlAvailable()` gates the button and `loadGenre` hides it. **The x-scale is derived per genre**, not fixed: art covers a century at ~44px/year, classical nine centuries at ~2.2, with the tick step (`TL_STEP`) chosen so labels land ~90px apart. Hovering a cluster blooms it open (`stepTimeline`), each group draws its real span as a bar behind it, zoom is anchored to the pointer (`tlZoomAt` — scaling alone slides your target off-screen), a horizontal wheel pans, and `clampTL` bounds the pan. Picking a school from the filter jumps to it (`jumpToGroup`).
- The preview panel pauses requestAnimationFrame when hidden — for physics assertions in evals, pump `step()` manually instead of waiting.
- Mobile layout kicks in under 700px width; the bottom-sheet panel replaces the side panel.

## The classical genre (generated, not hand-authored)

Classical is built by an importer, like the art constellation — the other three are hand-authored and stay that way.

- **`scripts/import-classical.mjs`** → `js/data/classical.js`, from `~/Desktop/Composers and Musical Movements/` (composers file → eras/schools/composers; connections file → 8 typed relationships with notes). Edit the markdown and re-run; the enrichment layers are merged back in so a re-import never wipes them.
- **`scripts/enrich-classical.mjs`** → `scripts/classical-enriched.json` (portraits, Wikipedia extracts, verified article titles). **The guard worth knowing:** the source already carries each composer's dates, so a Wikipedia match is accepted only if Wikidata's dates agree — ±5 years for an exact date, ±15 for a "c." estimate or anything medieval. A flat tolerance was tried and rejected Bernart de Ventadorn despite an exact death-year match. This caught John Adams → the US President, Chris Dench → Judi Dench, Antonio de Salazar → an 1889 namesake. A second scan (dates vs era) catches the undated, where no date test is possible: Charles II → "Charles Fox (composer)", Robert Wilson → "John Wilson". Both are pinned in `OVERRIDE`. **Re-running `--retry` only revisits failures** — a wrongly-*successful* match must have its cache entry deleted to be re-resolved.
- **`scripts/make-classical-batches.mjs`** / **`merge-classical-bios.mjs`** → `scripts/classical-bios.json`, written by a write→adversarial-verify fan-out. 739 repairs across two passes; the dominant fault was **near-verbatim copying from the Wikipedia extract** (classical articles are dense and well written, so writers drift into paraphrasing too closely — one batch had 30 of 45 entries with 7+ word runs), then **cross-record leaks** (Byrd's 1575 came from Tallis; Landini's superlative from Paolo da Firenze; Mouton's St Mark's from Willaert). No fabricated dates were found, which is what grounding in the harvest bought.
- Data shape: `n(id,name,era,school,life,works,alsoIn)` — **`role` = the school**, `life` = "dates · place", plus `works` from the source. `bySchool:true` makes the engine filter by school instead of instrument. 26 composers are listed under two schools; the second is kept in `alsoIn`.
- `generated:true` + `written:true` tell `validate.mjs` how strict to be: structural fields always, `blurb`/`bio` once written, and `life` permanently exempt (a patron reached only through a connection has no dates).
- 159 of the 712 nodes are **patrons, theorists and librettists**, not composers — they are folded into the school of whoever they are most tied to, and their bios must describe what they enabled, not call them composers.

### Audio for classical (a known gap, with one fix so far)

`playClip` seeds its search from `disco[0]`'s title. Classical nodes ship with an empty `disco`, so the engine just searches the composer's name and plays whatever is most famous — which for **John Cage returned 4'33", four and a half minutes of silence**. Perfectly correct, entirely useless.

**The general pass is done** (2026-08-17). Two halves:

1. **`scripts/harvest-classical-audio.mjs`** → `scripts/classical-tracks.json`. Seeds come from **Wikidata P800 "notable work"** (already harvested as `worksQ`), falling back to the leading clause of the source's `works` prose — guarded, because Bach's prose reads "the summation of the entire contrapuntal tradition", a gloss that would make a nonsense seed. A candidate is accepted only when the track title matches AND either the composer's surname appears in artistName/collectionName (diacritics folded — "Pärt: Portrait"), or the title is **distinctive**. Generic form-titles ("Ave Maria", "Requiem", "Symphony No. 5") always require corroboration: they are exactly where you would otherwise play the wrong composer's music. Result: **261 of 416 (63%)**, strongly era-weighted — Medieval 27%, Renaissance 47%, Baroque 56%, Romantic 77%, Modernism 73%. The rest get no seed rather than a guess.

2. **`byWork:true` on the genre** switches `itSearch` to work-first matching: verify by title, corroborate with the composer's name in artist or album, prefer corroborated hits. `artistMatch` is never used for classical, because iTunes credits the PERFORMER (searching Machaut returns The Orlando Consort).

**The gotcha that cost two rounds: plurals.** Reference works pluralise, catalogues don't — Wikidata "Brandenburg Concertos" / "Cello Suites" vs iTunes "Brandenburg Concerto No. 3" / "Cello Suite No. 1". Substring matching fails on exactly the most-recorded music there is. Hence `workTitleMatch()` (token-based, light plural stemming), kept **separate** from `trackTitleMatch` so jazz/hip hop/reggae keep the stricter song-title behaviour. The harvest script stems too — when only one side stemmed, seeds verified offline then silently failed to resolve in the app.

**Refinements after the first pass** (same day, from auditing what actually played):
- **Both providers are work-aware.** Only Apple was at first, so when Apple missed, the Deezer fallback — still matching on artist name — served Bach's Brandenburg No. 6 from *"Great for Baby's Brain, Mozart Effect and Pure Enjoyment"*. `pickWork()` is now shared by both.
- **Novelty compilations are demoted** (`_wJunk`): baby/sleep/relax/study/spa/"Mozart effect"/"50 best" and friends. Real recordings, poor thing to hear on a click.
- **Seedless composers get a fallback.** 451 nodes have no verified work, and `artistMatch` is exact — iTunes credits the performer, so they played *silence*, not something wrong. They now resolve when the release NAMES them, which took 20 sampled composers from 3 to 15.
- **Album corroboration must LEAD.** Allowing any album mention put Ulysses Kay on **William Dawson's** *Negro Folk Symphony*, via a multi-composer anthology that happened to list Kay. Classical releases are titled "Ockeghem: Missa De plus en plus", so the surname must fall in the album's first four words; artist or track-title mentions stay sufficient. Verified: keeps Ockeghem/Dunstaple/Pärt/Vivaldi, rejects "Black Composers Series, Vol. 9: Ulysses Kay".

## Lazy genre loading

Every genre used to load up front, so a visitor who only opened Jazz still downloaded all four datasets — classical alone is 290KB gzipped. Now only the genre being viewed is fetched: **first load went from 638KB to 160KB** (jazz) or 331KB (classical), and a fifth genre costs nothing until someone clicks its tab.

- **`window.MC_GENRE_LIST`** in index.html is the manifest — `{key,label,src}` per genre. The engine builds its **tabs from this**, not from loaded data, or only the preloaded genre would get one.
- **`window.MC_LOAD_GENRE(key)`** injects a data file on demand and returns a promise (deduped via `__mcLoading`, so double-clicks don't double-fetch). `switchGenre()` calls it when `GENRES[key]` is missing, then re-enters.
- **`window.GENRE_DATA` is created in index.html**, before the engine. This matters: each data file does `window.GENRE_DATA=window.GENRE_DATA||{}`, which preserves object identity, so the engine's `const GENRES` reference sees genres that arrive later. If the engine created it instead, a later file could replace the object and the engine would hold a stale one.
- index.html picks the **initial genre** (hash → `tmc_last` → first in manifest/`MC_CONFIG.genres`) and inserts only that data file before `js/engine.js`, since the engine needs its data present at startup.
- `parseHash()` accepts any genre **in the manifest**, loaded or not, so a cold deep link like `#/classical/timeline` works.

Verified after the change: all four tabs render, each loads on first click, cold deep links work, and only the viewed genre is fetched.

## Timeline for the three song genres (per-artist, not clusters)

Jazz/hip hop/reggae now offer the Timeline too, but the layout differs by necessity. Art has 85 dated movements and classical 66 schools, so they read as a sweep of clusters. **These three have only 7 eras each** — grouping by those gave seven fat blobs, which is worse than no timeline.

They do have something the other two don't: **every musician carries their own dates** in `life` ("b.1965 · American", "1920–1955 · American"). So `tlPerArtist()` (true when a genre has no `schools`/`movements`) switches `layoutTimeline` to a **beeswarm**: x is the person's own year, y is the first lane with room (`GAPX` 13px, `STEPY` 20px). Undated people fall back to their era's midpoint. `tlGroups` is left empty, so cluster labels and hover-bloom don't apply. **Hover therefore has to do the naming**: in per-artist mode `drawTimelineView` treats `hoverNode` as the focus (names them, names their connections, lights the ties), exactly as the globe does. Without that, scanning across the beeswarm showed no names at all and the view was unreadable — cluster mode doesn't have the problem because hovering blooms a group and labels its members.

Era `s`/`e` spans were added to all three data files to drive the axis — **these are considered approximations, not sourced**, and are the thing to adjust if a period looks wrong.

**Known semantic caveat:** the year used is the **birth year** (the first 4-digit number in `life`), so Louis Armstrong sits at 1901 though his music is 1925-60 — everyone reads ~25 years earlier than their work. Placing by an estimated active year (birth + ~25) would line the axis up with the music instead, at the cost of inventing a number. Huey's call.
